# 화면 구조 설계

## 1. 정보구조도 IA

본 정보구조도는 RGB·열화상 기반 태양광 구역 관리 플랫폼의 주요 화면과 메뉴 구조를 정의한다.

화면 구조는 일반 사용자의 점검 업무 흐름을 기준으로 구성하며, 발전소·구역 관리, 점검 관리, 이미지 업로드, AI 분석, 점검 결과 조회, 분석 결과 상세 확인 기능을 포함한다.

```text
인증
├─ 로그인
└─ 승인 대기 안내

사용자
├─ 대시보드
├─ 발전소 관리
│  ├─ 발전소 목록/등록
│  └─ 발전소 상세/수정
│     └─ 구역 관리
│        ├─ 구역 목록/등록
│        └─ 구역 상세/수정
│           ├─ 하위 설비 구조 관리
│           └─ 점검 이력 / 변화 추적
├─ 점검 관리
│  ├─ 점검 목록/등록
│  └─ 점검 상세
│     ├─ RGB·열화상 이미지 업로드
│     ├─ 업로드 이미지 목록 / 미리보기
│     ├─ 이미지별 AI 분석 요청
│     ├─ 분석 상태 확인
│     └─ 실패 사유 확인 / 재시도
└─ 점검 결과
   ├─ 점검 결과 목록
   └─ 분석 결과 상세
      ├─ 원본 / 결과 이미지 비교
      ├─ Bounding Box / Heatmap / Mask 확인
      ├─ 조치 후보 확인
      ├─ 검토 상태 변경
      └─ 이전 점검 비교 / 반복 이상 / 악화 여부 확인

관리자
└─ 사용자·운영 관리
   ├─ 사용자 승인 위젯
   ├─ 사용자 비활성화 및 상세보기 위젯
   ├─ 사용자 상세보기 클릭 시 관련 로그 확인
   ├─ 운영 로그 확인
   └─ 시스템 로그 확인
```

### 3-1. 화면 구분 기준

- 구역 관리는 발전소에 종속되는 하위 관리 기능이므로 발전소 상세/수정 화면에서 해당 발전소의 구역을 조회·등록·관리
- 점검 상세 화면은 점검 정보 확인, RGB·열화상 이미지 업로드, 업로드 이미지 미리보기, 이미지별 AI 분석 요청, 분석 상태 확인을 포함하는 중심 화면
- 이미지 업로드는 분석 입력 데이터를 준비하는 단계이며, AI 분석은 업로드된 개별 이미지를 대상으로 비동기 분석 작업을 요청하고 상태를 확인하는 단계
- RGB 이미지와 열화상 이미지는 각각 독립적인 분석 대상으로 처리하며, 이미지 유형에 따라 RGB-only 또는 Thermal-only 모델을 사용
- 점검 목록은 촬영·점검 업무 단위를 관리하는 화면이고, 점검 결과 목록은 AI 분석 결과를 기준으로 이상 후보, 조치 후보, 심각도, 우선순위, 검토 상태를 조회하는 결과 중심 화면
- 사용자 관련 로그는 특정 사용자의 로그인, 업로드, 분석 요청, 상태 변경 이력을 확인하는 로그이다.
- 운영 로그는 로그인, 업로드, 분석 요청, 검토 상태 변경, 관리자 작업처럼 서비스 이용 과정에서 발생한 주요 이벤트 이력이다.
- 시스템 로그는 API 오류, AI 분석 실패, 파일 저장 실패, DB 오류, Queue 오류처럼 시스템 구성요소의 장애 및 오류 추적을 위한 로그이다.
- 관리자 기능은 사용자·운영 관리 페이지로 구성하며, 사용자 승인, 사용자 비활성화 및 상세보기, 사용자별 활동 로그, 운영 로그, 시스템 로그 확인을 위젯 또는 탭 형태로 제공한다.
